# Kola

Kola is a **local-first, cross-platform universal reading and annotation application** for ebooks, PDFs, Word documents, presentations, spreadsheets, comics, and other readable document formats.

The goal is to build a fast, private reader for Linux, Windows, macOS, Android, and iOS from one Flutter codebase while still feeling native to each platform.

## Product identity

> **Read almost anything beautifully. Annotate it deeply. Keep your data. Understand your reading life. Continue anywhere without lock-in.**

Kola is built around:

- universal document support;
- Fidelity View + source-linked universal Flow Mode;
- best-in-class annotations;
- premium adaptive-native UI/UX;
- local-first storage and optional Bring Your Own Cloud sync;
- universal local search;
- Reading Intelligence, Reading List, and active reading-time tracking;
- migration/import/export and interoperability;
- read-aloud, dictionary/lookup/translation, and Parallel Read utilities.

Kola intentionally has **no AI-assistant layer and no dedicated study-system layer**. It is a reader, not an AI chat app, flashcard suite, mind-map tool, SRS system, knowledge graph, social network, or productivity super-app.

## Current implementation

Kola is in **Phase 2: PDF fidelity reading**, with parts of the later search and annotation milestones integrated.

Implemented today:

- local managed-copy/linked-file import and persistent SQLite/Drift library;
- real PDF rendering, page navigation, zoom and saved reading position;
- local full-text search with source-page jumps;
- PDF text selection, persistent highlights, notes/recolor/delete and conservative anchor/geometry recovery;
- adaptive Home/Library/Search/Insights shell and reader navigation;
- format/analyzer/unit/widget/native-PDF tests in GitHub Actions.

PDF is the only integrated renderer. Recognizing/importing TXT, EPUB, office files or comics does **not** mean those formats can be read yet. Flow Mode is deliberately disabled until source mapping and reading-order quality are ready. Focus Mode, document history/tabs, OCR, additional format engines and BYOC sync remain planned. See [live state](docs/PROJECT_STATE.md) and the [reader audit](docs/READER_AUDIT.md).

## Development

### Requirements

Use a current Flutter stable release with Dart 3.13 or newer.

### First setup

After cloning the repository:

```bash
bash tool/bootstrap.sh
```

The bootstrap script generates the native Flutter platform projects for Android, iOS, Linux, macOS, and Windows, resolves dependencies, runs analysis, and runs tests.

After that:

```bash
flutter run
```

For ordinary development checks:

```bash
flutter pub get
dart run build_runner build
dart format lib test
flutter analyze
flutter test
```

Native PDF tests use Flutter's built PDFium asset under `build/native_assets/<host>/`. Set `PDFIUM_PATH` to an explicit native library if your test runner stores assets elsewhere. These tests fail if the engine is unavailable; they are not silently skipped. Native platform projects are generated by the bootstrap script and are not present in the source checkout.

## Architecture direction

```text
Adaptive platform shell
  -> Flutter UI + Kola design system
  -> application/use cases
  -> Kola document domain
  -> DocumentAdapter registry
  -> format engines/parsers
  -> Kola Document Graph + SourceMap
  -> Fidelity View | Flow Mode | Search | Annotation
  -> Progress/Coverage -> Reading Intelligence
  -> SQLite/Drift + local files + disposable caches
  -> optional Sync Projection -> user-selected SyncBackend
```

Primary stack:

- Flutter + Dart;
- Riverpod;
- go_router;
- SQLite + Drift;
- SQLite full-text search;
- PDFium behind an adapter for PDF rendering;
- background isolates/workers for parsing and indexing;
- optional native/Rust capabilities only when profiling or format support justifies them.

## Core product rules

- Local reading works with zero network requests.
- No mandatory account or Kola-hosted cloud.
- BYOC sync is optional and never blocks reading.
- The live SQLite database is never synced as a file.
- Flow Mode and Fidelity View share document identity and annotations.
- Annotation anchors are source-linked, not screen-coordinate-only.
- Position progress, actual reading coverage, and active reading time are separate concepts.
- App chrome themes and reader themes/backgrounds are separate.
- Reader correctness and accessibility outrank decorative complexity.
- AI assistants and dedicated study systems remain out of scope unless that product decision is explicitly changed.

## UI/UX direction

Kola follows:

> **Calm reading surfaces + familiar structure + high craftsmanship + selective expressive interactions + native platform behavior.**

The product semantics remain consistent while navigation, chrome, menus, density, gestures, keyboard behavior, and other interactions adapt to platform, available window size, input devices, and accessibility settings.

The current prototype is intentionally tokenized so **Luminous Paper**, **Editorial Scholar**, **Soft Expressive**, and the **Kola Core** hybrid can be compared without rewriting feature logic.
